# 第五周代码阅读说明：先学会“看代码”，再学 MLP

这套作业的代码有多个文件。它们并不是八份互不相干的作业，而是一条流水线上的不同岗位：

```text
data.py
  准备数据
      ↓
models.py + optimizers.py
  造网络、造更新规则
      ↓
training.py
  反复训练参数
      ↓
evaluation.py
  只预测、算成绩
      ↓
reporting.py
  保存 CSV、画图
      ↑
run_step.py / run_mlp.py
  两个“总指挥”：按顺序调用上面的组件
```

这四份讲解文件按下面顺序读；每读完一份，都应当能在源代码里找到对应位置。

1. `01_实践一_一次更新逐行讲解.md`：只用两个样本，弄懂梯度、`backward()`、`step()`。
2. `02_数据和模型逐行讲解.md`：弄懂数据划分、标准化、张量形状、MLP 与 ReLU。
3. `03_训练评价与Adam逐行讲解.md`：弄懂小批量、整轮评价、最佳轮次、SGD 与 Adam。
4. `04_入口输出与组会讲解.md`：弄懂整个程序怎样串起来、结果文件怎样读、组会怎样讲。

这里的“逐行”不是要求你死背每个英文单词，而是要做到：看到一行代码，能说出它从哪里拿东西、做了什么、把结果交给谁。为了不让重复的 Python 符号把人绕晕，先把所有反复出现的符号一次讲清楚。

## 一、先把常见符号翻译成人话

| 代码写法 | 最简单的意思 | 例子 |
|---|---|---|
| `import torch` | 请 Python 把名叫 `torch` 的工具箱搬进来 | 后面可以写 `torch.tensor(...)` |
| `from torch import nn` | 只从 `torch` 工具箱里拿出 `nn` 这一个抽屉 | 后面可直接写 `nn.Linear(...)` |
| `as` | 取一个短名字 | 本周没有复杂别名；以后常见 `import numpy as np` |
| `def` | 定义一个可重复使用的小步骤（函数） | `def make_step_tensors():` |
| `class` | 定义一种“有固定字段的东西” | `class UpdateTrace:` |
| `return` | 把函数算出的结果交还给调用它的地方 | `return x, y` |
| `=` | 把右边的结果存进左边的名字；不是数学上的“永远相等” | `loss = loss_fn(pred, y)` |
| `==` | 问“左右两边是否相等” | `optimizer_name == "sgd"` |
| `:` | 开始一个有缩进内容的代码块 | `if ...:`、`def ...:` 后面都有它 |
| 缩进（开头四个空格） | 说明这一行属于上面的函数、循环或判断 | Python 用缩进代替大括号 |
| `()` | 调用函数、传入参数；也可包住一个表达式 | `model(x)` |
| `[]` | 列表、按位置取东西，或读字典里的字段 | `rows[1]`、`row["loss"]` |
| `{}` | 字典：给每个值贴名字 | `{"epoch": 1, "MSE": 0.5}` |
| `.` | 取某个东西的属性或功能 | `loss.backward()` |
| `,` | 分隔多个东西 | `x, y = ...` |
| `#` | 注释。Python 会完全忽略它后面的文字 | `# 反向传播` |
| 三个引号 `"""..."""` | 文档说明，通常写在文件或函数开头 | 解释用途，不参与训练 |
| `None` | “暂时没有值” | 还没反传时梯度是 `None` |
| `True` / `False` | 真 / 假 | `shuffle=True` 表示要打乱 |
| `float(...)` | 把一个数转成普通小数 | 便于打印、写 CSV |
| `f"...{变量}..."` | 把变量的值塞进一段文字里 | 用于控制台提示 |
| `-> float` | 类型提示：作者预计函数会交回一个小数 | 只是说明，不会强制计算 |
| `list[float]` | 类型提示：预计这是“由多个小数组成的列表” | 不会改变实际运行 |
| `|` | 类型提示中的“或” | `float | None` 是小数或暂时没有值 |

## 二、贯穿整周的五句核心代码

无论是实践一的两个样本，还是实践二的 265 条训练样本，真正改变模型参数的核心始终是下面五句：

```python
optimizer.zero_grad()
prediction = model(xb)
loss = loss_fn(prediction, yb)
loss.backward()
optimizer.step()
```

把它想成教人投篮：

1. `zero_grad()`：擦掉上一次练习写在白板上的“改进建议”。
2. `model(xb)`：按当前姿势投一次球，得到预测。
3. `loss_fn(...)`：量一量球离篮筐有多远，得到错误大小。
4. `backward()`：分析每个关节该向哪里调整，把建议写在每个参数的 `.grad` 上。
5. `step()`：教练（优化器）真正按建议修改姿势，也就是改权重和偏置。

必须分清：第四句**计算建议**，第五句**照建议改参数**。`backward()` 不会让权重自己变小；`step()` 也不会自己重新计算梯度。

## 三、代码中最重要的四类“东西”

| 名称 | 像什么 | 在本周是什么意思 |
|---|---|---|
| 数据 `x`、`y` | 题目与标准答案 | `x` 是输入特征，`y` 是要预测的目标 |
| 模型 `model` | 带很多可调旋钮的机器 | Linear 层的权重、偏置是旋钮 |
| 损失 `loss` | 总误差分数 | 本周是 MSE，越小越好 |
| 梯度 `grad` | 每个旋钮的调整建议 | 指方向，也表示调一点会怎样影响损失 |
| 优化器 `optimizer` | 根据建议拧旋钮的人 | SGD 和 Adam 是两种拧法 |

## 四、不要用“背代码”的方式学习

每次看一小段，都问自己下面四个问题：

1. 这行代码的输入从哪里来？
2. 它输出了什么，存在哪个变量里？
3. 它是只计算，还是会改变模型参数？
4. 它处理的是一条样本、一批样本，还是整份数据？

只要这四个问题能答出来，哪怕忘了函数名的拼写，你也是真的理解了训练流程。
